# Route by required control

Treat this as a decision process, not a ranked model leaderboard. Names, availability, limits and costs change. The research catalog is an audit snapshot, never a substitute for live discovery.

## Establish the execution surface

Record web UI, connected MCP tool, API, CLI, editor or Blender integration. Do not mix IDs, billing rules, input syntax or entitlements between them. Use current native tools when available. Do not probe another account, install an integration, purchase access or switch surfaces merely to evade a gate.

1. Resolve an exact command or named preset first. The official Higgsfield router distinguishes browsing from execution.
2. Discover candidate models for the actual task. Shortlist at most two compatible choices unless the user asks for comparison.
3. Inspect the selected model and the submitting tool. Map canonical media roles to that surface's schema. A model's backend name `image_references` is not automatically the tool's canonical role `image`.
4. Verify requested control combinations, not just individual features. Some modes make reference collections and first/end frames mutually exclusive.
5. Capture only relevant schema fields for preflight, including count, duration, resolution, sound, aspect ratio and any nested shot controls. Never treat an extensible JSON object as permission to invent a field.

## Choose the method

| Requirement | First method to evaluate |
| --- | --- |
| Approved appearance, modest movement | Image-to-video from a clean approved still |
| Match a performance or camera motion | Motion-reference route, with verified matching input roles |
| Exact product geometry or architectural travel | Deterministic 3D/blockout, then optional controlled stylization |
| Exact first and final compositions | Supported first/end-frame mode; inspect the interpolation |
| Multiple edited shots | Shot plan and actual multi-shot controls, or separately generated shots and editing |
| Precise spoken timing | Verified audio/lipsync route and source performance |
| Exact brand lettering or screen UI | Vector/HTML/compositing overlay; generate only the background where possible |
| Local image defect | Inpaint/edit with preserved source, rather than whole-image replacement |
| Existing usable video needing crop/grade/trim | Editor or post-production, before regeneration |
| Unknown model or new tool | Inspect live schema plus current official guide; do not inherit another family's syntax |

A fast tier is useful only if it tests the same risk. It may alter motion, duration, audio or reference support. Do not promise a cheap draft that the current route cannot produce. An accepted draft may be a better final base than a fresh expensive rerender.

## Refresh discipline

Refresh current capabilities and price before a paid submission or changed mode. Reuse the same task's inspected facts while unchanged. Reopen official documentation only when the selected version or an unresolved control requires it. Store a short capability record, not a transcript of every tool call.

Evidence precedence depends on the claim: current endpoint schema and quote govern executable inputs and cost; provider docs explain model behavior; platform docs explain workflows; practitioner accounts generate hypotheses. If they conflict, record the discrepancy and resolve the exact surface. Do not assert that a preset makes probabilistic generation deterministic.
